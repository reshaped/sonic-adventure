# 1ST_READ.BIN's kernels: the code each phase of a frame runs most, in the
# groups that run together. tools/ld.py lays them out first in the image's
# code, in the table's order, and fails a link where their lines take sets
# of the SH-4's caches that its docstring forbids. In SEGA's order of
# objects their lines can collide, and which collide moves with any code
# ahead of them.
#
# A row is KERNEL SOURCE FUNCTION. SOURCE is the source as the image's
# tables place it, src/draw/model.src for model.c's functions, or for a
# source config/dreamcast.mk adds, as DC_ADDED gives it. A row places the
# section that holds FUNCTION, so matrix_load_parent's places all of
# cache.src's code, its one P section. An over row, over KERNEL KERNEL,
# lets the two kernels' lines take one set; each names two kernels where
# one seldom runs among the other's code. ld.py keeps the lines of a
# kernel's literal pool off the operand cache's sets of the lines of a data
# row's section, or of the last data port.h's LINKED_LAST_DATA marks, that
# a pool word of the kernel, or of one it runs with, points into. It moves
# the section or the last data on by whole lines, reckoned from the link
# without moves, and fails the link on a pair the moves leave.
#
# A window row, window KERNEL LINES [OFFSET], gives a kernel LINES lines:
# its code, OFFSET lines in, then room. The windows follow each other in
# the table's order, so code that grows within its window moves nothing
# outside it, and the row likeliest to grow goes last. ld.py fails a link
# where a kernel outgrows its window. It starts .rodata and .bss on the
# operand cache's 16 KB, so that no code that grows moves a datum to
# another set. A data row, data SOURCE NAME, puts the section of SOURCE's
# object that holds NAME first in its output section, in row order, where
# no change to the rest of the data moves it.
#
# A starts row, starts OUTPUT [OUTPUT] [OUTPUT], names the output sections
# of an image's data, of .rodata, .data and .bss, that ld.py starts on the
# operand cache's 16 KB, with windows or without, so that nothing ahead of
# one that changes size moves its data to another set. A packed row,
# packed, says the image starts none of them, as one whose load area has
# no room for them must. An image whose table has neither row, or that has
# no table, starts those config/dreamcast.mk's DC_STARTS names, where its
# tables place code.
#
# A last row, last SOURCE, puts the code port.h's LINKED_LAST marks in
# SOURCE's object ahead of the rest of the image's last code, in row order.
# A change's last code is measured where it lands, so a change whose last
# code lands after another's adds its row after the other's, and the code
# measured first keeps its sets. All of the last code still moves with any
# change to the size of the code between the windows and it.
#
# A warm row, warm SOURCE FUNCTION, puts the section that holds FUNCTION
# after the last window, ahead of the image's other code, at the place
# order.txt gives it. So the code a frame runs most outside the kernels,
# which runs between their calls and decides which of their lines it
# evicts, takes the sets its place gives it, and no change to other code
# moves it: not to the code linked after it, and not to a warm row that
# grows within the bytes up to the next row's place. ld.py checks none of
# their sets. order.txt records heat.txt's hash, the address .text starts
# at, the place and size of each kernel row's section, and the place of
# each warm row's. ld.py fails a link where a warm row runs past the next
# row's place, or where the heat, .text's start or a kernel row's section
# isn't as the record has it, and names what moved. make dc-order then
# writes order.txt again, as it must after a row here is added or
# removed, and says what the record held otherwise. It moves no warm row
# that fits where it lies. It gives one that fits no longer, or a new
# one, a place on a line's start with a spare line after it, by heat.txt,
# a measurement of how often a frame ran each stretch of code, and writes
# the warm rows here in their places' order. A row fits no longer where
# it outgrew the bytes up to the next row's place, where its alignment
# rose off its place, or where the last window's end moved past it.
# Nothing else moves a warm row, and then that row alone moves. make
# dc-order SEARCH=1 also searches the whole block for places that cost
# less, which moves every row, and make dc-order PACK=1 lays the rows in
# this table's order with no byte free among them, which moves each row
# after the first free byte. Each is a change to measure.
#
# A row that takes another place leaves its bytes free, and the image's
# other code follows the last warm row, so a row that moves past the
# others moves that code and lengthens the image. A window row that names
# warm, window warm LINES, gives the warm rows a window as a kernel's
# does: the image's other code starts at its end, so no warm row that
# grows or moves within it moves a line of that code, or the image's
# length. ld.py fails a link where the last warm row passes the window's
# end, and make dc-order gives a row a place only under it. A window
# wider by a multiple of 256 lines leaves each line after it on its set.
#
# A cold row, cold SOURCE, puts all of SOURCE's code after the last code,
# and its read-only data, its data and its .bss after the last data, in row
# order. So code that runs too seldom for the sets it takes to matter, and
# changes often, moves no other code but a later cold row's, and no datum
# outside the cold rows' sources, while it takes the same names of the C
# the link-time compile compiles. ld gathers the cold sources' strings and
# constants where the first cold row's lie, so one a later row gains moves
# the data of the rows before it too. A cold SOURCE holds no common symbol,
# which .bss would take: the link fails on one.
#
# The object of each SOURCE a row names keeps its own code, which the row
# places: the link-time compile, which compiles the image's other C whole,
# takes none of it and inlines none of it elsewhere. The compile does read
# which names of its C each other object takes. It keeps a function one of
# them calls, and may inline or drop one that only its own C calls. So an
# edit to a row's source, or to an assembled one, that adds the first use
# outside the compile of one of its functions, or removes the last, changes
# what the compile writes, and moves the code and data linked after it, the
# last code and the cold rows' among them. Once a source joins or leaves
# the rows of any image's table, make dc compiles each C object again, and
# an edit that leaves the rows' sources as they were compiles none.
#
# rare, mesh, model, present and matrix take under 256 lines together, so
# none lies over another. walk lies over rare, the draw code a frame runs
# least or apart from the motion trees. sweep, which runs apart from the
# draws, lies over mesh, model and present, but keeps off matrix, which it
# calls. land, which only the land's loop takes, lies over present, which
# that loop doesn't call. clip, which only a model with near points takes,
# lies over rare, matrix and walk, and keeps off mesh, which calls it for
# each meshset. sprite, which runs among present and matrix, lies over the
# others, and its row order leaves only process_blends' cases on
# njGetkmPointer and njSetkmPointer, which each sprite calls.
